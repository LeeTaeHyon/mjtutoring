## 1. 포트 레지스터 핵심

각 포트의 `DDRx` 비트는 방향(1=출력, 0=입력), `PORTx`는 출력 래치(출력일 때 1=High, 0=Low), `PINx`는 실제 핀의 입력 상태 읽기에 사용한다. 입력에서 `PORTx=1`은 내부 풀업 활성화다. `x`는 A/C 등 포트 문자다. 레지스터에 쓴 값과 실제 연결된 회로의 전압·점등은 구별한다.

| 명령 | 결과 | 의미 |
| --- | --- | --- |
| `DDRA |= 0x07;` | DDRA 비트 0,1,2가 1 | PA0~PA2 출력; 다른 방향 비트 유지 |
| `DDRC |= 0x07;` | DDRC 비트 0,1,2가 1 | PC0~PC2 출력 |
| `PORTA = (PORTA & ~0x07) \| 0x01;` | 하위 3비트 = 001 | PA0만 High; 상위 비트 유지 |
| `PORTA = (PORTA & ~0x07) \| 0x04;` | 하위 3비트 = 100 | PA2만 High |
| `DDRA |= (1U << PA7);` | DDRA bit 7 = 1 | PA7 출력 추가 |
| `PORTA |= (1U << PA7);` | PORTA bit 7 = 1 | PA7 High |
| `PORTA &= (uint8_t)~(1U << PA7);` | PORTA bit 7 = 0 | PA7 Low |

주의: `DDRA = 0x01`은 PA0만 출력으로 만들고 PA1은 입력이다. 두 출력 핀을 LED 양극·음극으로 쓰는 회로라면 양쪽 모두 출력으로 설정해야 한다. 다만 이 수업에서는 **핀 → 저항 → LED → GND**를 기준으로 삼는다. 서로 다른 두 GPIO에 LED를 바로 잇지 않는다.

### 배선 그림을 말로 읽기

- 기본 능동 High: `PA0 → 전류 제한 저항 → LED 애노드(긴 다리/+); LED 캐소드(짧은 다리/−) → GND`. PA0=1일 때 켜진다. PC0도 같은 방식. 실제 하드웨어에서는 LED별 저항을 사용하고 핀·포트 전류 한계를 확인한다.
- PA7 추가 예시: `PA7 → 저항 → LED 애노드; 캐소드 → GND`. `DDRA |= (1U<<PA7)`, `PORTA |= (1U<<PA7)`이면 켜진다. PA7은 같은 포트의 *다른 비트*이며 PA0의 귀로가 아니다.
- 능동 Low 예시: `VCC → 저항 → LED 애노드; LED 캐소드 → PA7`. 출력 PA7=0이면 전류를 싱크하여 켜지고, PA7=1이면 꺼진다.
- **공통 캐소드 7-Segment:** COM=GND, 각 세그먼트 핀에 저항을 거쳐 High를 주면 켜진다. **공통 애노드:** COM=VCC, 각 세그먼트에 Low를 주면 켜진다. 모듈의 실제 a~g·COM 핀 번호는 제품 핀맵을 확인한다. COM에 단일 저항을 몰아 넣지 않는다.

## 2. 프로젝트 생성과 코드 실행

1. Microchip Studio/Atmel Studio 7에서 **File → New → Project → GCC C Executable Project**, Device는 **ATmega128**을 선택한다. 생성된 `main.c`의 내용을 예제 파일 내용으로 **통째로 교체**한다. 두 예제는 모두 `main()`을 가지므로 각각 별도 프로젝트에서 실행하거나 하나씩 교체한다.
2. `#include <avr/io.h>`로 레지스터 이름을, `#include <util/delay.h>`로 `_delay_ms`를 가져온다. `F_CPU`는 **헤더보다 앞**에 정의한다. 예제는 1 MHz이고, 프로젝트/시뮬레이터 클록을 이에 맞춘다. 실제 보드 클록이 다르면 `F_CPU`와 설정을 함께 변경한다.
3. **Build → Build Solution (F7)**. `_delay_ms(1000)`은 AVR libc의 상수 지연 호출이다. 최적화 설정과 클록 정의가 실제 지연의 정확도에 영향을 준다. 시뮬레이터에서 1초 구간 전체를 매 명령 Step Into로 지나가면 매우 느리므로, 지연 호출 뒤에 브레이크포인트를 두거나 잠시 지연을 10 ms로 줄여 살펴본다.
4. **Debug → Start Debugging and Break (Alt+F5)**에서 Simulator를 선택한다. **Debug → Windows → I/O View**에서 PORTA, PORTC의 DDR/PORT 레지스터를 펼친다. 환경에 따라 메뉴 이름이 다르면 디버그 창에서 I/O View를 검색한다. `show_lights` 또는 `display_digit` 호출 뒤에 브레이크포인트를 놓고 Step Over (F10)한다.
5. 보드 없는 시뮬레이터의 `PORTA/PORTC` 값은 **코드가 출력하도록 설정한 래치 값**이다. LED가 실제로 켜졌다는 측정은 아니다. `PINA/PINC`의 물리적 상태나 LED 전류도 회로 모델 없이 단정하지 않는다.

### 예제 A — 두 묶음 LED 신호등

[traffic_light.c](traffic_light.c): PA0/PC0=빨강, PA1/PC1=노랑, PA2/PC2=초록. 두 포트에 같은 상태를 출력한다. 순서는 빨강 1초 → 초록 1초 → 노랑 0.5초 → 반복한다. 코드는 `DDRA |= 0x07; DDRC |= 0x07;`을 쓰므로 다른 핀 설정은 유지한다.

| 정지 위치 (`show_lights` 실행 후) | PORTA & 0x07 | PORTC & 0x07 | 켜질 LED (기본 배선) |
| --- | ---: | ---: | --- |
| `show_lights(RED)` | `0x01` | `0x01` | 빨강 |
| `show_lights(GREEN)` | `0x04` | `0x04` | 초록 |
| `show_lights(YELLOW)` | `0x02` | `0x02` | 노랑 |

초기화 직후 `show_lights(RED)`가 한 번 더 호출된다. 이는 출력 모드 설정 직후 래치를 빨강으로 맞추는 용도이고, 루프 첫 단계와 같은 값이다. 실제 배선에 글리치를 피해야 한다면 PORT 래치를 먼저 설정하고 DDR을 출력으로 바꾸는 순서를 검토한다. 전원 투입 중 안전이 중요한 장치는 별도 회로 설계가 필요하다.

### 예제 B — 1자리 7-Segment

[seven_segment.c](seven_segment.c): PC0=a, PC1=b, …, PC6=g; 각 선마다 저항; DP 미사용. 0~9를 1초 간격으로 반복한다. 기본 `COMMON_ANODE 0`은 공통 캐소드다. 애노드형이면 `#define COMMON_ANODE 1`로 바꾸고 COM을 VCC에 연결한다. **두 코드는 PC0~PC2 사용이 겹치므로 동시에 구동할 수 없다.** 별도 프로젝트/실습으로 사용한다.

| 숫자 | a~g 패턴 (bit6…0) | 공통 캐소드 PORTC & 0x7F | 공통 애노드 PORTC & 0x7F |
| --- | --- | --- | --- |
| 0 | `0111111` | `0x3F` | `0x40` |
| 1 | `0000110` | `0x06` | `0x79` |
| 2 | `1011011` | `0x5B` | `0x24` |
| 8 | `1111111` | `0x7F` | `0x00` |

## 3. 오류 찾기 (Zoom 화면 공유)

| 증상 | 확인 순서 | 수정 |
| --- | --- | --- |
| `_delay_ms` 미선언/빌드 실패 | `util/delay.h` 포함, `F_CPU` 선언 위치, 정확한 오류 줄 | `F_CPU`를 헤더 위에 정의; `#include <util/delay.h>`; **GCC C Executable / ATmega128** 선택 |
| 전부 안 켜짐 | 빌드 성공 여부 → DDR 출력 → PORT 비트 → GND/COM → LED 극성/저항 | `DDRA/ DDRC`의 대상 비트를 1; 전원·GND와 저항 경로 수정 |
| 예상 색과 실제 색 불일치 | 핀 매핑 PA0/1/2 또는 PC0/1/2, 배선 색상, 코드 비트 | 비트와 LED 배선을 일대일 대응 |
| 7-Segment 숫자가 뒤틀림 | 실물 a~g 핀맵과 PC0~PC6 연결, 공통 극성 | 핀 번호가 아니라 **세그먼트 이름**으로 매핑, 필요하면 패턴 재배열 |
| 시뮬레이터 값은 바뀌는데 불이 안 보임 | Simulator는 MCU 레지스터 관찰, 물리 LED 모델/보드가 없음 | I/O View의 DDR/PORT를 증거로 기록; 실물 점등은 주장하지 않음 |
| 예상보다 빠르거나 느림 | `F_CPU`와 프로젝트/실기기 클록, 최적화 | 같은 Hz로 맞추고 다시 빌드 |

`PORTA=0x01`처럼 포트 전체에 쓰면 PA7 등 다른 비트가 지워진다. 예제의 마스크 연산은 하위 3비트만 바꾼다. 비트별 변화가 불분명하면 레지스터를 이진수로 적어 보자.

## 4. 단계별 학생 과제

1. **기본 (15분):** `traffic_light.c` 빌드 후 RED/GREEN/YELLOW 각각에서 DDRA, DDRC의 하위 3비트와 PORTA/PORTC의 하위 3비트를 기록한다. 예상값과 일치하는지 설명한다.
2. **응용 (10분):** PA7에 능동 High LED를 추가한다고 가정하고, 기존 출력 설정을 보존하는 초기화·점등·소등 코드 세 줄을 작성한다. PA7을 빨강 동안만 켜려면 `show_lights`가 PA7을 보존한다는 점을 이용해 어디서 토글할지 적는다.
3. **확장 (10분):** `seven_segment.c`에서 0, 1, 2, 8을 디버깅해 패턴 값을 확인한다. `COMMON_ANODE`를 1로 바꿔 0의 하위 7비트가 `0x40`이 되는 이유를 설명한다.
4. **도전 (선택):** `digits[10]`을 수정하지 않고 역순(9→0) 표시로 바꾼다. `uint8_t`에서 0 아래로 감소할 때 언더플로가 생기므로 종료 조건을 신중히 작성한다.

**제출:** 빌드 성공 화면 1장, I/O View 값 또는 예상 레지스터 표 1장, 극성에 따른 0 표시값 설명 2문장. Simulator가 불가능한 환경이면 코드와 예상 상태 표로 대체한다.

### 진행자 확인 답안

- 과제 1: DDRA/DDRC 하위 3비트 `111`; PORTA/PORTC는 빨강 `001`, 초록 `100`, 노랑 `010`.
- 과제 2: `DDRA |= (1U << PA7);` / `PORTA |= (1U << PA7);` / `PORTA &= (uint8_t)~(1U << PA7);`. 빨강 구간 진입 시 켜고 다른 구간 전에 끈다.
- 과제 3: 공통 애노드는 점등 세그먼트에 Low를 주므로 0의 `0x3F`를 하위 7비트에서 반전하면 `0x40`.
- 구두 질문: DDR=1이어도 PORT=0이면 능동 High LED는 꺼진다. 공통 애노드의 Low는 점등이다. 시뮬레이터 PORT 값은 실제 LED 점등 증거가 아니다.
